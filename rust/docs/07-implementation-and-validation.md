**从零实施与验收计划**

Rust 版从空配置和新数据根开始，按照本设计交付。旧版本兼容、导入、命令别名、数据接管、旧任务转换与旧版回退均不在范围内。现有源码只提供平台经验、功能场景和已知失败案例，不形成实现必须复制的历史约束。

**1. 第一次运行**

默认根为 `%LOCALAPPDATA%\AppProxy`，支持 `--home` 指定空目录。创建本产品的 marker、owner SID、store UUID 和 schema 1 manifest；未知非空目录拒绝初始化。不会搜索 `.app-proxy-home.json`、旧 scopeRoot、旧 manifest、旧实例目录或旧任务。

首次交互选择应用、原版/空白实例及代理；新增实体全部生成新 UUID。原版只启动当前安装应用的默认数据，空白实例创建新的自有数据。2026-09-20 按用户决定，普通启动不再预扫描外部进程是否运行，单实例转交与目录占用由应用处理。本工具已核验会话和未决请求仍防重；不能宣称接管外部旧进程的启动环境或让新参数对它生效。

新程序使用 AppProxy 专属系统资源命名空间。发现端口占用、同实例已运行或不属于本产品的任务/快捷方式，均按外部资源处理；不为解决冲突清理其他工具。

**2. 实施批次**

| 批次 | 内容 | 退出条件 |
|---|---|---|
| M0：平台关键路径 | 固定 toolchain/deps；普通 EXE 参数/环境/身份；MSIX 原生 helper；ETW 与管道权限 | 包内 helper、进程身份、事件权限均有可重复证据 |
| M1：最小启动闭环 | 三 crate；新 schema/store；coordinator/IPC；LaunchEngine；普通 EXE + 自行启动的 sing-box，手动上游最小配置 | 从空目录到 create/launch/status/stop 完整通过；重复启动、unknown 与取消契约通过；不复用外部运行服务 |
| M2：实例和代理 | 模板、Codex/Claude、MSIX 存储、快捷方式；多 profile 托管 core、订阅解析、一键安装内核 | 原版与多实例共存，代理检查/配置恢复、安装/取消/失败重试和格式 fixtures 通过 |
| M3：Guard | 原生 ETW helper、前台授权、降级扫描、精确纠正、限流/恢复 | 纠正只影响目标实例；代理失败、监听断连、不可读身份均符合策略 |
| M4：可发布产品 | 中文菜单、创建部分成功恢复、原位置快捷方式维护、卸载、诊断和打包 | 干净机器完整验收、权限与故障恢复通过，发布清单完整 |

每批完成都应有可运行的纵向链路。先写下本批实际输入、预期行为和验证方法，再实现支撑它的最少代码；不提前铺下一批的空模块、扩展接口或菜单选项。M0 可以有实验实现，进入正式版本前收敛成一个生产后端；不同时维护原生、Node 两种启动实现。用户已确认开始实现，2026-09-19 首批 M0 代码及已通过/未通过范围见 [验证记录](D:/app_proxy/rust/TEST-RESULTS.md)。

**3. M0 实验清单**

| 实验 | 具体动作 | 成功证据与失败处理 |
|---|---|---|
| 参数/环境 | 受控 child 回显结构化 args、cwd、指定 env，经中文/空格/引号/尾反斜杠路径启动 | 数据逐项一致、父进程环境不变；否则修正 Windows 参数封装 |
| 身份 | 查询同用户目标的 PID/创建时间/SID/session/image/命令行，再用句柄关闭 | 与系统观察一致；读取拒绝返回 unknown，不能扩权掩盖 |
| MSIX | PowerShell 激活 Rust package-child；普通/虚拟化清单测试包，加 Codex/Claude 原版与分身 | 能收到可信回执，目录从包外可见且归属正确；不通过就先修订包适配 |
| ETW | 受保护目录部署最小 listener，授权普通客户端只读事件 | 低权限客户端不能改 action/写 helper；跨用户/session 和伪 server 被拒绝 |
| 取消/迟到 | helper 在 claim 前、claim 后、spawn 后分别暂停；取消并恢复执行 | 不产生重复实例，未知结果保持锁定；仅到期不能误判无进程 |
| HTTP/TLS | 经本机测试代理 CONNECT 到受控 HTTPS；正确/错误 CA、错误端口 | 明确代理路由和证书验证；选择通过测试的 TLS backend |

基于这些结果确定 MSRV、依赖锁、Windows 最低 build 和具体平台 API 组合。若某个 SDK 接口不可用，修订边界或采用已验证的小型平台桥接；不能仅用 cargo check 通过作为系统兼容证据。

**4. 功能验收矩阵**

| 层级 | 必须覆盖 | 证据 |
|---|---|---|
| 模型/纯逻辑 | tagged union、引用完整性、env set/unset/大小写、受管参数、模板能力和格式拒绝 | 单元测试与公开无凭据 JSON fixtures |
| 状态机 | 每阶段失败/取消、同 request-id 重放、client 断线、spawn 无回执、配置中途改变 | 可注入时钟/进程/存储/代理故障的契约测试 |
| Windows 进程 | 中文路径、空格、引号、cwd、环境、PID 复用、SID/session、读取权限 | 受控 child EXE 回执和系统身份核验 |
| coordinator/IPC | 并发冷启动、错 major、超大 frame、假 server、跨 session、慢订阅者 | 命名管道集成测试及拒绝码 |
| core/proxy | 两个出口、CONNECT/TLS、普通 HTTP 伪装、外部端口占用、更新与恢复失败 | 受控代理/服务器 + 真 sing-box check/run |
| parser | 六协议、多种配置格式、ALPN、%XX、Base64、重名、清空选择、深度/体积限制 | 独立输入/期望模型 fixtures，不要求复制旧解析器错误 |
| Guard | 冲突参数、原版与多分身、命令行未知、helper 残留、运行会话绑定快照、限流 | 受控实例，所有无关进程始终存活 |
| MSIX | 包更新、清单虚拟化、LocalState、原版/分身、迟到回执和消费竞态 | 测试包 + 指定版本 Codex/Claude 实机记录 |
| 存储/恢复 | manifest 替换中断、操作 journal 每阶段故障、损坏 JSON、路径替换、文件占用 | 临时 store 故障注入；不使用真实用户目录做破坏测试 |
| 集成/安装 | 本工具链接创建/修复/移除、ACL、UAC 取消、部分完成、任务被用户改写 | 原生系统状态回读，外部资源保持原样 |

测试夹具使用临时根、动态空闲端口和受控 EXE。端口提前检查后仍可能被抢占，以实际 bind/启动结果为准，不用端口扫描当预留。ETW 事件测试不触碰用户现有原版进程。

**5. 实机验收场景**

记录 Windows edition/build、目标 package version/family/AppId、Rust/内核版本、存储模式、网络条件和证据。至少执行：

1. 干净环境解压发行包，首次创建 store，发现应用/代理，创建快捷方式并启动。
2. Codex 原版 + 两个空白实例，Claude 原版 + 空白实例，验证数据目录和实例匹配。
3. 应用包更新后由相同 family/AppId 解析新 EXE，既有 Rust 实例目录保持。
4. 代理先正常后失效、探测后失效、内核启动失败，确认无自动直连 fallback；运行中代理故障保留应用并提示，启动前验证失败不创建新目标。
5. Guard 误启动纠正、监听退出、扫描降级、UAC 取消和前台修复；不同实例不误伤。
6. coordinator 在关键启动/配置阶段退出，重启后核对 journal，未决结果不重复启动。
7. 默认卸载只解除本产品管理，保留应用及实例数据；被用户改写的快捷方式不强删。
8. Codex/Claude 受管原版的 Guard 默认开启；监听授权、认证连接和初次扫描通过后可显示 active。外部误启动经完整身份确认后关闭并通过代理重启；本工具启动前代理验证失败不创建主目标。此能力不承诺阻止外部进程首次联网。
9. 只创建分身时不登记原版、不询问原版代理；原版从原入口正常启动，Guard 不干预它。关闭/移除受管原版保护不影响分身。
10. 两个不同代理 profile 由同一自有 sing-box PID 提供，分别通过自己的端口验证对应出口；多个应用可共享同一 profile，新增应用不重复启动内核。

目标应用的登录、模型对话、Code/Cowork 若未执行，报告明确未验收；不能从网络进程连接本地代理推断全部业务通过。内核出口探测属于工具证据，目标实际请求需另行观察。

**6. 性能验收**

固定一台机器和应用版本，热/冷启动各 30 次，分 core 已运行/未运行两类；报告 p50/p95 和安装解析、代理准备、spawn/receipt 的分段耗时。Guard 记录 event→callback→身份确认→stop→重启，空闲资源观察至少 10 分钟。

比较 Rust 各阶段瓶颈即可，旧版不是性能或行为准入基线。初次结果用于锁定后续回归阈值，不预先承诺具体毫秒数/内存大小。发行包体积统计 launcher 和原生依赖；sing-box EXE/DLL 的独立安装下载体积另列，不混入产品发行包。

**7. 发布与运行维护**

实现阶段运行 fmt、clippy、单元/契约/Windows 集成测试和打包校验，具体命令以实际 Cargo workspace 为准。M0 已有实际构建与测试记录；未实现的功能不因 Cargo 构建成功就视为验收通过，也不把 JSON 示例校验称为构建成功。

发布包包含 CLI、host、有限 MSIX 桥接和版本/协议/配置格式信息，不包含 sing-box。单独验收已有 EXE 复用并自行创建进程、已有外部服务不接入、缺少内核时一键安装及取消/失败重试；安装器记录下载内核的来源/许可证，不覆盖用户现有安装。发布说明列出实际验收 OS build 和应用包版本；Windows 10/11 支持按实测列出，ARM64/macOS 不因代码可编译就宣称支持。

新产品内部的配置 generation 失败恢复、安装操作恢复仍必须实现；它们用于保证本次操作一致性，与旧版兼容无关。首次发行不需要跨产品升级器。Rust 版本自身更新限定固定目录，先核对协议/配置版本，不自动读取 TS 数据。

2026-09-20 范围收敛：不做跨目录升级或移动后入口重定向，也不做 Windows 登录任务被外部删除后的专用检测、自愈或修复流程。这两项不再列为待办或发布门槛。保留固定目录使用、正常登录自启的创建/查询/移除，以及已接受但未完成操作的显式恢复。已有只读查询仍如实报告入口不可用，不能把历史创建回执当作当前就绪。
