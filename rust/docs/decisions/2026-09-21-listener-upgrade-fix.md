# 监听组件升级失败修复

首次安装正常，但已有监听的第一次升级在安装器 `setup-prepare` 阶段失败。最初只输出 `GUARD_LISTENER_RELEASE_CONFLICT`，实际是管理员安装子进程已经失败，前台随后读到旧监听版本。

管理员安装现在将每次操作的结果写入 Guard 受保护目录中的独立诊断文件，前台在子进程失败时读取对应诊断并写入 Setup 日志。实机重试捕获到 `系统找不到指定的文件 (os error 2)`。

根因在读取可选的 `listener-upgrade.json`：文件尚不存在时，路径检查通过 `std::fs` 返回 `Error::Io`，升级代码只识别 `Error::Windows` 的文件不存在错误，因而未进入新建升级事务的分支。现在统一两种错误表示；访问拒绝、记录损坏等错误仍然停止升级。新回归测试修复前复现同一错误，修复后通过。

另修复已发布程序但后台配置未完成时的恢复流程：修复版安装包可以核验现有程序、按原事务恢复自有文件，再开始新版本安装，不再要求始终重跑出错的旧安装包。恢复前持久化状态，使恢复中断仍可继续；被用户修改的文件不会被覆盖。

验证：升级恢复测试 8 项、监听安装票据测试 4 项、监听升级记录测试 3 项通过；Clippy all-targets、格式和差异检查通过。实际安装结果另见 `.tools/setup-listener-fix/`。

修复版本 `b05819314ed5` 已打包并重试正式安装；本次 Windows 返回 `GUARD_INSTALL_CANCELLED`，未执行管理员监听升级。尚不能宣称正式监听和登录入口已经恢复，需完成管理员授权后核验。
