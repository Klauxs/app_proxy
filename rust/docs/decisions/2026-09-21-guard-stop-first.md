# Guard 先关闭、后登记与重启准备：2026-09-21

## 旧路径拆解

上轮正式 Claude 样本从进程创建到确认关闭 453.175 ms，到带代理新主进程创建 2597.157 ms。关闭前的工作如下：

| 阶段 | 样本耗时 | 原有工作 | 本次处理 |
|---|---:|---|---|
| ETW 事件到达 | 0.647 ms | 收到进程启动提示 | 保留 |
| 目标识别 | 15.704 ms | 精确进程句柄、映像、用户/会话、实例归属、主进程角色及代理参数 | 保留 |
| 纠正登记 | 298.156 ms | admission/configuration 锁、恢复配置事务及历史启动状态、多次读取启动记录、跨请求日志编号冲突检查、原子写入 Accepted 记录 | 写盘和历史恢复移至关闭后，删除重复请求查询；增加锁等待、历史恢复、记录写入分段计时 |
| 关闭前准备 | 73.665 ms | 再读配置/请求、复用或核验安装和数据目录、解析物理资源、取得资源锁、恢复旧资源声明、写入 Reserved | 全部移至关闭后，作为重启准备 |
| 停止授权 | 44.160 ms | 再读配置与请求、写入停止意图、资源冷却/次数记录 | 关闭前只保留当前配置与观察版本核对；停止结果和重启限流记录移至关闭后 |
| 原生停止 | 13.538 ms | 在已固定的精确句柄上检查存活、TerminateProcess、等待该进程退出 | 保留 |

其余约 7 ms 是阶段间调度间隔。不能从旧的聚合打点区分 298 ms 内各项历史 I/O 的占比；本次已补细分，避免把这一数值都称为写盘耗时。

## 新路径与边界

ETW 事件确认确切主进程未按配置使用代理后，在后台 worker 中短暂持有 admission/configuration gate，核对保护仍启用且配置版本、代理端点未变化，然后直接在已保留的原生句柄上关闭并确认退出。关闭前不恢复历史、不写日志、不取得重启资源锁、不扫描子进程、不检查代理健康，也不重新解析目标命令行。

确认退出后，在同一后台工作流程保存带有停止结果的纠正请求，再取得重启资源、检查代理、准备参数并重启。停止结果与新请求合并为一次原子记录，不再先写 Accepted，再写停止意图，再写停止确认。平台发出的停止回执不能从磁盘反序列化伪造。原有持久启动意图和进程创建去重仍保留在重启前。

关闭后原有的两轮占用扫描合为临近重启的一轮；只用它判断是否可以创建新实例，不挡住主进程关闭。后台补扫描发现的确切主进程也转入这一流程。

重启资源冷却/次数限制仍在关闭后的资源准备中执行；它限制自动重启，不再让未带代理的目标继续运行。关闭成功但记录失败时显示 `GUARD_STOPPED_RECORD_FAILED`，后续“未发现进程”不能把它覆盖成正常状态。

**崩溃取舍**：若守护在原生关闭成功后、持久记录完成前崩溃，该应用保持关闭，不自动猜测或重放重启。配置已禁用、身份不一致、目标已退出时不发出关闭；记录失败、资源冲突或代理不可用时不直接启动应用作为替代。

这次没有移除配置锁的等待，也没有把后台所有写盘并发化。停止与已提交配置修改的次序仍由短暂的配置 gate 确定；正式测量会单独报告排队与 gate 等待，不能承诺任何系统负载下固定的停止延迟。

## 正式实测发现的包激活与重复主进程问题

首次部署后的主进程 PID 44928 在 **60.386 ms** 确认关闭，但该轮重启失败，不能计作完整通过。Windows AppModel 日志显示，随后给这个已关闭进程配置 AppX 容器时返回 `0x80070005`；01:15:16.588 的包激活则返回 `0x80073D00`。后者对应 Win32 错误 15616，本机系统消息明确为“无法启动应用程序，因为该程序当前正在更新。”因此该次包激活失败可确认是更新期间禁止启动，不能归因于关闭过早。同期间出现的另一个未带代理主进程 PID 26704 被“已有请求进行中”条件跳过，直到旧请求失败后才从补扫描纠正，实际等待约 20.8 秒。用户指出额外主进程可能由 Claude 升级拉起，与更新日志吻合，但未逐个核实进程父链。更新导致的激活失败与 Guard 跳过新主进程是两个独立问题。

补充修复：

- 已有请求不再抑制新未代理主进程的精确检查和关闭；关闭后复用仍在执行的重启或已确认的会话，不再另起第二个重启。
- 已确认会话自身仍按历史代理绑定保护；不会因后来改了代理设置而把它当作新误启动目标。
- 包启动只在同一个一次性 ticket 仍为 Pending 时有限重试激活，总共最多 3 次；Consuming/结果不确定、取消、截止后都不重试，不生成新的 ticket。补充原生双 helper 并发消费测试，确认只创建一次应用。
- 增加包激活结果、重试及桥接系统错误码的可选计时事件。

补充修改后的 **50 项 Guard 回归、9 项包启动回归通过**（另 1 个 child fixture ignored）；最终 Clippy/fmt/Release 通过。本段补充后没有重复全量 474 项。证据 `guard-final-tests.log`、`package-final-tests.log`、`clippy-final.log`、`release-final.log`。首次失败保存在 `failed-attempt-1.json`、`appmodel-first-failure.json` 及 `timing.ndjson`，没有被后续成功记录覆盖。
